# DSH 上下文 SDK 产品需求

更新日期：2026-10-03。本文描述项目要求；当前已有 DSH 源码和设计资料，以下 SDK 能力均待实现。

## 1. 项目目标

开发一个嵌入 DSH 的上下文管理 SDK，让 Agent 在长会话中保持当前目标和关键约束，按需找回历史细节，并在模型上下文预算内继续执行任务。

DSH 是首个接入宿主。SDK 核心与 DSH 适配层分开，便于后续接入其他 Agent；首版围绕 DSH 完成可用闭环。

## 2. 职责与范围

| 部分 | 负责内容 |
| --- | --- |
| DSH | 用户交互、Agent 主循环、模型调用、工具执行、审批、中断与执行恢复 |
| 上下文 SDK | 原始事件管理、任务状态、历史压缩、检索、模型输入组装及自身数据清理 |
| DSH 适配层 | 会话事件映射、模型消息格式转换、接入配置与会话生命周期对接 |

首版只管理单个 session 内的上下文，各 session 数据隔离。全局记忆、跨 session 共享和多租户服务不属于首版范围。

首版暂不加入任务完成阈值自学习，以及根据用户反馈自动调整阈值和触发追问的策略。待基础流程稳定后，再讨论是否加入并另行安排；现有任务状态判定与轻量 TP 更新不依赖自学习。

## 3. 核心要求

| 能力 | 要求 |
| --- | --- |
| 原始事件 | 保存用户消息、模型回复、工具调用及结果，保留顺序、角色和来源；重复接收同一事件不能重复写入 |
| 四层上下文 | 保持 Rules / Constraints、Compressed History、Recent Raw、Current Task State 四层结构 |
| 当前任务状态 | 维护目标、状态、进度、未解决事项和下一步；用户修改要求或工具返回后及时更新，每次更新有原始事件依据 |
| Episode 压缩 | 从固定区间的 Raw 生成独立摘要，原文保留；压缩成功提交后才切换历史视图，失败时保留旧视图和 Raw |
| Task Package | 按功能 / 主题保存简单用途介绍、相关 Raw 引用及分条摘要；常规压缩发现关联后，由独立后台队列读取新增 Raw 并追加，不等待任务完成、不清空 Recent Raw |
| 历史检索 | 首版只使用关键词召回（lexical）与语义召回（semantic），采用固定融合策略，去重后按 token 预算返回，支持摘要检索和原文回查；模型暂不调权，Graph、recency、importance 不参与首版排序，跑通后再考虑优化 |
| 上下文组装 | 每次模型调用前重新构建，包括工具执行后的下一次调用；完整请求计入 token 预算，并预留输出空间 |
| 生命周期 | 支持关闭和重新打开；删除 session 时清理 SDK 原文、摘要、任务状态、索引与缓存，后台迟到结果不得恢复数据 |

Rules 保留当前有效约束；Recent Raw 保留尚未被成功压缩的原文。历史信息不能自动成为新指令，旧 TP 条目不能覆盖当前状态。

## 4. DSH 接入要求

1. 优先通过 DSH 插件和已有扩展点接入，避免将 SDK 核心逻辑直接写进 Agent 主循环。
2. 以 DSH 会话事件作为原始依据，明确 SDK 存储的事件映射与处理位置，避免出现两份互相矛盾的历史。
3. 保留消息角色、来源以及工具调用与返回的对应关系；SDK 生成的模型可见内容须能通过 DSH 日志重建。
4. 通过配置启用或关闭 SDK。启用时明确它与 DSH 原有压缩功能的分工，同一段历史只能由一个机制负责切换视图。
5. 对接 DSH 的会话创建、恢复、关闭和删除。DSH 自身保存的消息副本与日志由宿主清理，SDK 删除成功不能代表宿主副本也已删除。
6. 压缩作为独立后台作业，正常触发无需通知或询问用户；内部允许有限的主动召回、工具交互与模型请求，并限制次数、累计 token 和执行时间。期间继续接收、展示并持久保存新事件，暂不修改已发布上下文；下一次主模型调用前完成交接，将新增事件与压缩结果纳入新快照。超时、超限或检索不可用时明确处理，不能静默丢弃新要求。

7. TP 摘要与主循环、常规压缩隔离：主模型调用和 Episode 发布均不等待 TP；失败独立重试，共享模型额度时采用低优先级及并发预算保护主请求。

接入点参考 [DSH 架构](../dsh/docs/architecture.zh.md)与[压缩子系统](../dsh/docs/subsystems/compaction.zh.md)。具体接口和默认策略仍需结合代码验证。

## 5. 基本流程

1. 创建或恢复 DSH 会话，绑定同一 session 的 SDK 实例。
2. 将新消息和工具事件交给 SDK 保存并更新任务状态。
3. 每次模型调用前，由 SDK 选择规则、当前状态、相关历史与 Recent Raw，生成本轮输入。
4. DSH 执行模型和工具，将结果送回同一事件链，进入下一次上下文构建。
5. 达到压缩条件时生成 Episode；发现功能 / TP 关联时交付 Raw 引用，独立后台只追加新增功能摘要。历史查询按需读取已发布 TP 条目，最新未压缩内容由 Recent Raw 和任务状态承接。
6. 关闭时保留可恢复数据；删除时协同清理宿主与 SDK 的会话数据。

## 6. 验收条件

- 在 DSH 中完成连续对话及至少一轮工具调用，SDK 组装的输入符合模型消息协议。
- 多次修改目标、约束及切换任务后，下一次相关调用仍使用当前有效要求，任务进度区分已执行与已验证。
- 压缩期间输入新消息，事件不丢失、不重复；压缩失败或超时后仍保留原始记录。
- 能从历史摘要追溯原文；检索结果不会跨 session 读取数据。
- 请求在配置的模型预算内；必保留内容超限时返回明确错误。
- 关闭后可重新打开；删除后不能检索到 SDK 管理的数据，迟到作业不能写回。
- TP 慢作业、失败或重试不阻塞主模型调用和 Episode 发布；同一来源重复触发不重复追加，摘要保留变更关系，并可补查尚未进入 TP 的 Raw。
- 可查看各层 token 用量、压缩及检索状态、TP 待处理材料、失败或降级原因，便于判断问题发生在哪里。

## 7. 开发顺序

1. 建立 DSH 事件与会话适配，完成 Raw 保存、任务状态和上下文构建的最小闭环。
2. 加入 Episode 压缩、Task Package、历史检索与原文回查。
3. 完善异步交接、恢复与删除，使用上述验收场景验证，再比较检索策略与运行成本。

详细接口和一致性方案沿用 [上下文 SDK 设计](../research/context-management/上下文SDK设计.md)；待研究问题见 [调研任务清单](../research/context-management/上下文SDK调研任务清单.md)。
