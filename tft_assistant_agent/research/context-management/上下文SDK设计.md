# 上下文 SDK 设计

更新日期：2026-10-03。本文汇总上下文 SDK 构想、实现契约与调研任务，首个接入宿主已确定为 DSH（DeepSeek Harness），项目要求见 [产品需求](../../docs/产品需求.md)。除已确认的方向与范围约束外，API 名称、组件划分、默认策略和实验路线均为待验证建议；当前仓库尚未实现本 SDK。

## 1. 定位、约束与宿主边界

### 已确认的方向

- SDK 嵌入 DSH，核心上下文能力与 DSH 插件 / 适配层分开；DSH 保留 Agent 主循环、模型和工具执行等宿主职责。
- 以可插拔 SDK 接入 Agent，当前只管理单个 session 的上下文，不设计全局记忆或跨 session 共享。
- 四层为 Rules / Constraints、Compressed History、Recent Raw、Current Task State；不增加中间轻度压缩层。
- 首版检索仅采用关键词召回（lexical）与语义召回（semantic），固定融合，模型暂不调权；Graph、recency、importance 不参与首版排序，跑通后再考虑优化。
- Episode 与 TP 的持久压缩内容来自 Raw；任务状态允许递归增量更新。
- TP 采用轻量功能 / 主题目录：简单介绍 + 相关 Raw 引用 + 各 Raw 中该功能相关的摘要，只追加新增材料；生成不依赖任务完成，也不清空 Recent Raw。
- TP 摘要由独立低优先级后台队列直接读取 Raw 生成，主循环、Context Builder 和常规 Episode 发布均不等待 TP；常规压缩只提供关联线索与 Raw 引用。
- 单次压缩是一个独立后台作业，允许有限的主动召回、工具交互与模型请求；内部调用和重试共用次数、token 与执行时间预算。
- session 删除后，所有相关上下文数据都需要删除，迟到后台任务不得恢复数据。

### 职责边界建议

SDK 负责事件保存、状态更新、压缩调度、索引检索、上下文组装与自身数据清理。宿主负责 Agent 主循环、模型和工具执行、消息展示、中断与重启策略，以及外部操作的幂等和运行检查点。SDK 的事件与任务状态不能替代完整 Agent 执行恢复。

SDK 可以管理多个互不共享数据的 session 实例，但每个实例的读写和工具均绑定一个 session。模型不能通过工具参数任意切换 session。

首版建议一个进程内对单 session 串行提交状态和视图变更，同时允许模型调用、一个 Episode 压缩作业与 TP 生成在后台推进。多进程并发写同一 session 暂不作为默认能力；若以后支持，必须另行定义存储级并发协议。

## 2. 对外接口草案

管理器创建或打开 session；后续方法作用于绑定 session 的对象。方法默认采用异步接口，类型和错误语义先于具体框架适配确定。

| 方法 | 输入重点 | 返回与契约 |
| --- | --- | --- |
| `create_session(config, rules)` | 会话配置、适用规则 | 新 session 对象；生成不复用的 session 标识 |
| `open_session(session_id)` | 已存在且有效的 ID | 恢复对象；不存在或删除中则报错，不能隐式重新创建 |
| `append(events, idempotency_key)` | 按因果关系描述的事件批次 | 持久写入回执及事件序号；同键同内容重试返回原回执，同键不同内容报冲突 |
| `build_context(budget, tool_schemas, output_schema)` | 模型窗口、输出预留、工具和输出格式 | 不可变 ContextSnapshot；内部完成必要等待、状态追平与预算校验 |
| `retrieve(query, top_k, token_budget)` | 查询、SDK 配置和限制下的条数与长度上限；首版不接收模型权重 | MemoryHits，含来源、版本、固定融合策略版本、实际生效参数和降级原因；不直接改写任务状态 |
| `read_raw(refs, token_budget)` | 当前 session 内的证据引用 | 原文片段、来源与截断标记；禁止通过引用跨 session 读取 |
| `update_task(task_id, patch, expected_version, source_event_ids)` | 最小状态修改和证据 | 新 TaskState；版本冲突明确返回，禁止整份旧状态覆盖 |
| `compact(reason)` | 手动触发原因 | Episode JobHandle；也可由策略自动触发，重复触发合并或排队 |
| `update_tp(tp_id, raw_refs)` | 当前 session 的功能 / TP 与新增 Raw 片段引用 | TP JobHandle；独立后台生成并幂等追加条目，不等待任务完成，不阻塞主循环或 Episode 发布 |
| `get_job(job_id)` / `wait_job(job_id, timeout)` | 当前 session 的作业及截止时间 | 作业状态；等待超时不等于作业已取消 |
| `delete_session()` | 当前 session | DeletionReport；全部受管数据清理完成才返回完成，未完成时列出残留类别 |
| `close(mode, timeout)` | 等待作业结束，或取消并收敛作业 | 释放实例资源；Raw 与已提交结果保留，可重新打开；不得误当成删除 |

模型工具先只暴露 `retrieve`（可命名为原设计的 `retrieve_memory`）和 `read_raw`。删除、版本提交、压缩锁、任务调度由宿主和 SDK 调用。模型产生的状态 patch 必须经 SDK 校验后才能提交。

`append` 成功表示事件已持久保存，不表示状态提取、压缩或索引已经完成。语义上的首次任务识别可由状态提取器处理；宿主已知的 task_id 可直接提供。`build_context` 不再次接收并写入同一用户消息，避免事件重复。

宿主显式修改任务也必须关联已有 Raw；SDK 可用同一事务追加状态变更事件并提交 patch。不能产生只有状态、没有变更依据的旁路写入。

## 3. 数据契约与组件

### 最小数据契约

| 对象 | 建议字段和约束 |
| --- | --- |
| RawEvent | `session_id / event_id / seq / kind / role / content或artifact_ref / task_id / turn_id / call_id / input_snapshot_id / occurred_at / recorded_at / source_type`；可选字段按事件类型填写 |
| TaskState | 原五项任务字段，加 `state_version / processed_through_seq / source_event_ids`；扩展见专门文档 |
| Episode | ID、连续来源区间、原文引用、压缩正文、生成策略版本和发布状态；引用与内容都属于 session |
| TaskPackage | session_id、tp_id、功能 / 主题、简单介绍、目录 revision 与条目集合；用途介绍不承载当前进度或完成状态 |
| TPEntry | entry_id、稳定 raw_id / source_raw_spans、该功能相关的摘要；保留条件、来源与变更关系，可附已有事实身份和版本 |
| ContextSnapshot | snapshot_id、不可变 blocks/messages、through_seq、state_version、context_version、各层 token 用量、入选证据 ID、降级信息和选取诊断 |
| MemoryHit | 类型、内容、原文引用、任务与时间范围、版本、召回及排序信息；明确是历史证据而非新指令 |
| JobHandle | job_id、kind、固定来源范围、基准版本、状态、错误与尝试次数 |

关键决策与约束可在现有记录上附 `fact_key / fact_revision / scope / supersedes` 及 Raw 来源引用，用于跨 Episode、TP、分类视图和任务状态识别同一事实。事实语义版本与状态 / 快照版本分开；同一事实被再次提取不自动新增版本。该元数据与有效版本索引不构成新的上下文层，具体字段和识别方法见 [文本压缩具体方案第 2.6.1 节](./文本压缩具体方案.md)。

`seq` 表示 session 内持久接收顺序，不代表模型已经看到该事件。工具调用和返回通过 call_id 关联，模型输出通过 input_snapshot_id 表明基于哪个输入生成。中途到来的新消息不得被误认为已被在途模型处理。

大文件、图片和工具大结果可以以受管引用存储，首版是否支持各模态待定；引用也必须遵守 session 生命周期。诊断记录默认保存 ID、原因和计数，避免无限复制正文。

### 内部组件

| 组件 | 责任 |
| --- | --- |
| Event Store | Raw、序号、幂等回执、片段读取与关联数据清理 |
| State Manager | 任务识别、状态 patch、证据校验、状态流转和版本 |
| Compression Scheduler | Episode 作业与交接，以及独立低优先级 TP 队列；分别管理固定来源、预算、重试与发布 |
| Retriever | 关键词与语义索引、查询范围、两路召回、固定融合、去重与原文发现 |
| Context Builder | 四层选择、预算、协议合法性、一致快照和交接等待 |

组件是逻辑职责，不要求分别部署或使用独立数据库。生命周期控制统一协调这些组件的删除和后台提交资格。

## 4. 每轮调用与 Context Builder

宿主最小流程：`append 输入 → build_context → 模型/工具执行 → append 结果 → 下一次 build_context`。用户在执行期间可继续 append；是否中断在途调用由宿主决定。SDK 不接管消息展示。

构建步骤建议：

1. 检查 session 有效性。存在在途 Episode 作业时，下一次主模型调用前先等待交接，或完成显式失败回退；等待采用有限超时策略，不能在尚未解决交接时将待合并事件插入旧的已发布上下文。
2. 选定事件边界 H，取得反映该边界的一致任务状态和历史视图；不能将 H 之后的状态配给 H 之前的输入。版本变化时重新取快照，或使用可追溯的对应版本。
3. 初始排列为 `Rules → Current Task State → 选中的历史 → Recent Raw`。保留原四层定义，历史可附回查原文，工具调用结果仍遵守宿主消息协议。
4. 根据任务进行可配置预取；合并 Episode、TP、检索结果中的重复证据。避免把当前错误的历史版本当作现行状态；不要求把所有 Episode 都塞进输入。
5. 保持角色、来源、工具调用关联；对历史引用进行去重不能破坏当前工具调用与返回配对。
6. 计算完整模型请求的 token：四层内容、工具定义、输出格式及协议开销。要求输入 + 输出预留 + 安全余量不超过实际模型限制。
7. 优先减少低相关历史；不得静默截断必保留规则、新用户要求或未闭合工具交互。必要时尝试安全压缩；仍不可满足预算则返回 BudgetExceeded。
8. 发布本轮不可变 ContextSnapshot。随后新到的事件属于后续快照；若宿主改变本轮输入，需要重新构建。

工具原文回查结果可能作为真实 tool result 写入 Raw，历史区域的重复展示应去重，但不能删除当前协议所必需的 tool result。构建用快照与原始存储分离，改变展示不会改写过去的 Raw。

### 关键事实的有效版本与跨表示去重

1. 在本轮事件边界 H 内解析规则、决策和任务状态引用，选定实际使用的事实版本。明确修改 / 撤销且有来源依据时才替代旧版本，不能凭摘要生成时间判断当前有效性。
2. 当前执行查询默认使用该边界内有效版本；历史查询可选择旧版本和变更关系。旧 Episode / TP 保留来源时点的内容，不改写为当前状态。
3. 同一事实出现在多个分类或概览中时，选择必要的可读表示；summary、propositions、decisions、constraints、TP 与状态中的重复表达不要求全部注入。进度、下一步、条件、原因与独立约束不能因有关联而一并删除。
4. 优先减少历史与派生区域的重复内容，保留必需的 Rules、Recent Raw 与合法工具交互。不能仅按来源事件 ID 去重；同一事件可包含不同事实。无法确认语义等价时保守保留，并记录选取原因。
5. 快照记录实际使用的事实身份和版本、来源与去重诊断，使后续规则或决策变更不改变已发布输入。引用必须解析为正文或明确报告不可用，不能让模型只看到孤立标识。

## 5. 异步 Episode 和 TP 协议

### Episode：固定区间、追加尾部、原子发布

令 C 为已发布 Episode 连续覆盖到的事件位置，B 为本次安全压缩边界。

1. 首版同一 session 同时最多一个 Episode 作业，读取 `(C, B]` 的稳定 Raw。B 避开未闭合工具交互；具体分段粒度待研究。
2. 已经在执行的主模型请求继续使用已取得的不可变快照，结果可直接展示。新用户消息和模型 / 工具结果即时追加到 Raw，`seq > B`，不等待压缩，也不只保存在内存缓存；这些事件构成待合并尾部，暂不修改已发布模型上下文。待合并是视图状态，可由 Raw 与已提交位置恢复，不要求再维护一份独立消息正文。
3. 后台产出先写为不可见的候选结果并检查格式、引用和必要信息。提交时检查 session 仍有效、基准位置仍为 C。
4. 原子发布 Episode 并将位置推进到 B。只有发布成功，Recent Raw 视图才切到 B 之后；原文仍保留。构建器随后选定本轮边界 H，按顺序读取 `(B, H]` 的待合并事件，追平相应任务状态后发布新快照。H 之后的事件留给下一次构建，不修改已发布快照。这里保证的是事件覆盖的记账一致性，不代表摘要无损。
5. 下一次主模型调用前完成该作业的交接，包括工具循环中的下一次模型调用；当前已经生成的回答可先展示，接收新用户输入无需等待。正常触发和后台执行不要求通知或询问用户，但终止失败、无法继续或需要用户操作时须明确报告。等待期间不持有压缩提交需要的锁；发布和快照读取使用短时原子操作或互斥。
6. 失败或基准不匹配不能推进位置，保留旧视图与全部 Raw。超时需要回退时，先通过作业状态 / 发布资格协调，防止迟到结果与回退并发生效；随后选定 H，将未压缩 Raw 及待合并新事件重新构建为完整快照。只有该完整请求仍符合预算，才能按明确配置降级继续；否则报告暂不可构建，不能用遗漏新增事件的旧快照继续调用。

### 单作业内的主动召回与资源预算

七阶段属于一次压缩作业的内部处理。模型可主动调用 `retrieve` / `read_raw`，读取结果后继续请求模型；不要求整个作业只发起一次模型请求，也不为每个逻辑阶段固定安排独立调用。

1. 作业固定 `(C, B]`、基准视图版本、来源不超过 B 的 Rules / Task State 快照。召回可读取同一 session 中 B 之前的相关历史与 Raw，但不能吸收 B 之后的新增事件；检索结果用于参考和证据回查，不直接更新主循环状态。
2. 配置项建议包含 `max_model_requests`、`max_tool_calls`、`max_total_tokens`、`max_tool_result_tokens` 和 `job_timeout`。字段名与默认值待验证；每项预算都有限，不能依靠模型自行停止。
3. `max_model_requests` 计入读取工具结果后的续请求、实际发出的失败请求、重试和候选修复；`max_tool_calls` 统计每次工具调用，同一请求中的多个调用分别计数。重复触发同一作业不能重置预算。
4. `max_total_tokens` 累计本作业每次模型请求的实际输入与输出用量；重复发送的历史、提示词、工具 schema 及已进入模型输入的工具结果都计入。工具返回另受长度上限约束，未发送给模型的返回不能重复算成模型 token。usage 不可得时采用明确的保守估算并标记。
5. 每次模型请求和工具调用前检查剩余次数、token 及时间，模型请求预留输出预算并设置生成上限；临近耗尽时收敛为最终候选，不能继续无界召回。重试与修复使用原作业剩余预算。
6. 预算耗尽、超时、取消或失败时停止新增调用。已有候选仅在通过格式、来源与必要信息校验后才可提交；没有合格候选则报告未完成，保持旧视图和 Raw，按上述交接失败策略处理。
7. 作业记录实际调用数、工具数、token、来源引用和终止原因；含 session 内容的作业记录随 session 删除。session 删除或作业失去发布资格后，任何迟到返回均不得更新上下文。

例子：R100 写入 Raw 后触发作业，固定 B=100；后台召回历史并生成摘要。期间用户 R101 和在途模型回复 R102 继续持久保存与展示，已发布上下文保持不变。摘要提交后，下一次主调用构建 `Episode + Raw101、Raw102` 及相应规则 / 状态；若构建中收到 R103，则按本次选定的 H 决定它进入本次或下一次快照，不丢弃也不重复合并。

进程崩溃后，恢复读取持久事件、已发布位置与作业状态；未发布候选可丢弃或重算，重试不能生成重复生效的 Episode。摘要可见性和覆盖位置必须一起提交。跨存储索引允许通过持久发布清单和幂等索引任务跟进；索引滞后时需要源存储回退或显式降级，不能假定所有索引立即一致。

如果近期一个未闭合交互本身超过预算，优先由宿主限制工具返回或外置大结果；不能通过非法截断该交互来强行推进压缩边界。

### TP：轻量目录、增量追加与独立发布

TP 保存功能 / 主题的简单介绍和相关 Raw 的分条摘要。介绍只描述用途，任务进度和完成状态由 Current Task State 表达；条目直接从相应 Raw 生成，不从旧 TP 或 Episode 摘要推导新持久事实。

1. 常规压缩发现功能关联时，交付候选关联和固定 Raw 引用，由独立 TP 队列处理；关联发现与队列恢复方式待验证。常规压缩不执行 TP 摘要生成，Episode 发布不等待 TP。
2. TP 作业只处理新增 Raw 片段，保留变更、条件和验证状态；同一 Raw 可分别关联多个 TP。按 session、TP 与稳定来源范围幂等追加，不重建完整任务快照。
3. 主循环及下一次主模型调用不等待 TP，构建器使用已发布条目；TP 不使用 Episode 交接屏障，不改变覆盖位置、Recent Raw 或当前任务状态。TP 失败只影响其自身重试。
4. 首版同一 TP 可串行追加、合并重复通知；独立限制后台并发与模型预算，共享额度时保留主请求容量。发布前检查 session 有效性，删除开始后全部 TP 发布失效。
5. 目录 revision 仅在成功发布新条目时递增，不表示任务完成或事实有效性；条目与 Raw 引用用于回放。TP 可能滞后于 Recent Raw，查询可补查未压缩原文，不自动等待 TP 追平或加载整个目录。

完整结构、登录功能示例及旧方案的历史研究内容见 [文本压缩具体方案第 4 节](./文本压缩具体方案.md)。接口和字段名仍为实现草案；旧 `snapshot_task(stage/completion)`、大小修改版本与完整 TP 快照不作为首版默认接口和更新规则。

## 6. 检索、证据与信任

- 首版仅使用关键词召回（lexical / BM25）与语义召回（semantic / 向量检索），两路结果采用固定融合策略，去重后按数量和 token 预算返回；模型暂不调权，首版工具不暴露五权重参数。
- 具体融合算法和参数仍待实现与验证，基线运行时固定配置并记录策略版本。不能把不同原始分数直接当作同尺度相加。
- Graph、recency、importance 不参与首版排序。早期五权重和模型调权设想保留为后续研究，先跑通两路召回再评估优化。
- 当前有效性与新近性分开；来源引用、新旧版本、撤销关系和适用范围仍须处理，历史查询可读取旧版本，不能因停用 recency 而省略有效性判断。
- 支持任务级、Episode 级和原文级查询；摘要未命中时还要有 Raw 的词法或范围发现路径。
- top_k、返回 token、检索轮数和总调用成本都可限制；证据不足时允许报告不足，不能为填满结果补造事实。
- 原文来源属性在压缩与检索后继续保留。工具、文件中的文字不能自动升级为 Rules；历史记忆不自动获得用户指令的权限。
- 原文、摘要、索引、图关系和缓存均限定 session。即使暂不做多租户服务，也不能让不同 session 串读。

## 7. 失败处理、关闭和删除

| 情况 | 建议行为 |
| --- | --- |
| 事件写入重试 | 用幂等键去重；写入成功与后台处理成功分别报告 |
| 状态 patch 过期 | 返回 StateConflict 或有限重算；不覆盖新状态 |
| 压缩失败或候选不合格 | 维持旧视图和 Raw，有限重试并记录原因 |
| TP 慢作业或失败 | 主循环与 Episode 不等待；保留已发布条目和 Raw，独立有限重试并报告待处理来源 |
| 索引不可用或滞后 | 明确退回可用检索路径，或返回 RetrievalUnavailable；不冒充完整召回 |
| 内容超过预算 | 返回 BudgetExceeded，说明各层用量及可调整项 |
| 等待超时 | 返回 JobTimeout / 待处理状态；是否取消由独立策略决定 |
| close | 停止该实例接收操作，等待或取消并收敛作业，保留可恢复的数据；关闭未完成时报告状态 |
| session 删除 | 先关闭新读写并使后台提交失效，再收敛作业与清理所有派生数据；支持幂等重试 |

删除以生命周期状态和后台提交检查协调；发布和“开始删除”的先后顺序必须由同一个提交协议判定，不能仅在作业启动前检查一次。

清理范围包括 Raw、Episode、TP 目录 / 介绍 / 条目 / 来源关联 / 修订记录、任务状态、Rules / Pin、幂等回执、索引、图关系、缓存、临时文件、含 session 内容的作业和诊断记录。清理尚未完成时保留最少的删除进度以便重试；完成后不得保留可恢复正文的 SDK 副本。删除过程中取到的在途结果不再对外发布。

宿主已取得的消息副本、外部模型请求、宿主日志和备份不能靠 SDK 的数据库删除自动收回，接入方必须对接其保留和清理机制。只有 SDK 的全部受管存储适配器确认清理完成，DeletionReport 才能标记 SDK 范围内完成。

## 8. 配置与适配器

- 注入模型调用器、token 计数器、存储和索引适配器；不绑定单一 Agent 框架或模型供应商。
- 配置模型窗口、输出预留、Trigger / Target、各层预算、超时、重试、压缩和 TP 触发策略，以及检索能力开关；压缩作业另配置内部模型请求数、工具调用数、累计 token、工具返回长度与总执行时间上限，具体约定见第 5 节。
- TP 配置独立后台并发、低优先级调度、调用与 token / 时间预算；共享执行资源时保留主循环容量，具体数值待验证。
- 将策略版本、压缩提示词版本和 embedding / 索引版本关联到生成结果，后续可比较和重建；迁移方案待研究。
- 提供框架无关的数据块，再由消息适配器转换为宿主模型协议。来源和工具关联不能在转换中丢失。
- 首版可先使用一种持久存储实现；接口不得假定所有后端支持跨系统事务。存储适配器需声明原子发布、幂等和删除能力。
- 首版两路召回的融合策略固定、可回放。模型调权、Graph、recency、importance 等后续实验须在基线跑通后独立验证收益，不作为首版运行前提。
- 任务完成阈值自学习及根据用户反馈自动调整阈值、触发追问的策略暂不加入首版，也不纳入当前调研排期；待基础流程稳定后另行讨论和安排。现有任务状态判定与轻量 TP 更新不依赖自学习。

## 9. 诊断与验收基线

记录本次构建选入 / 排除哪些证据及理由、各层 token、状态处理位置、压缩区间、等待时间、检索参数与降级。区分“没存到、没检索到、检索到但没入上下文、已入上下文但模型没用对”。含正文的诊断数据也随 session 删除。

验收覆盖：连续改要求、历史问题、任务切换和重开、工具失败、长工具返回、压缩期间多次输入、重复写入、压缩超时、进程重启、删除期间后台回写，以及 TP 积压 / 失败不形成主循环等待依赖、重复追加、变更关系与未压缩 Raw 补查。不能只看压缩比或摘要是否通顺。

核心指标：任务成功率、约束遵守率、事实错误率、证据召回率、状态滞后、上下文超限率、构建 / 等待延迟、前后台总 token 与费用。一致性测试单独检查无事件丢失、无重复发布、无状态回退和删除后无回写。
