# 第一版后深入研究计划

记录日期：2026-10-12。

状态：本文整理自本次对话中助手建议的实施后研究计划，尚未执行或验证。先完成[第一版实现计划](./第一版实现计划.md)，以第一版的固定测试结果和错误记录作为比较基线，再按问题选择研究方向。

## 1. 研究目标与推进方式

用户提出的总体目标是：

> 在固定基础模型和输入条件下，能否通过数据设计与后训练，让 Agent 更可靠地更新用户记忆，并改善后续多轮决策？

第一版先把主要模块做成能运行的简单版本；这一阶段逐个模块做实验、训练和优化。优先研究第一版已经暴露的问题，每次明确改变了什么，再比较效果和成本。

本文沿用已有上下文管理研究中的模块划分。新产品的会话范围、长期记忆归属和最终宿主仍需确定；旧研究中的 DSH、单 session 范围不作为新产品的最终架构，关系见[产品方向与技术选型](../../docs/产品方向与技术选型.md)。

## 2. 第一优先级：记忆更新、数据设计与后训练

这条研究线最直接对应项目目标，建议在第一版完成后优先推进。

### 2.1 要研究什么？

检查系统能否正确判断：

- 什么值得记住？
- 什么应该修改旧记忆？
- 什么只是临时条件或未来计划？
- 用户纠正之后，怎样避免继续使用旧信息？

例如，用户说“如果拿到那个 offer，我可能搬去上海”，系统是否会错误地把当前居住地改成上海？这是一个可以从错误记录出发研究的具体问题。

### 2.2 可以尝试哪些优化？

按下面的顺序推进：

1. **分析第一版的错误。** 找出经常失败的情况，例如把条件句当成已经发生的事实。
2. **针对错误补充训练样例。** 增加“明确改变”“暂时改变”“条件尚未满足”等容易混淆的例子。
3. **改进提示词，建立更强的未训练版本。** 先确定单靠更清楚地表达任务要求，能改善到什么程度。
4. **用正确示例微调记忆更新模块。** 让模型学习如何根据新信息做出正确更新。
5. **使用相同对话重新运行，比较前后差异。** 同时检查记忆是否更准确，以及后续回答和选择是否更好。

比较时保持基础模型、测试对话和上下文预算等条件一致，只改变本次需要比较的数据、提示词或训练方案。不同方法产生的记忆差异属于要观察的结果。

用于补充训练的样例与最终测试分开保存；最终测试保留未用于训练和调试的对话，用来检查改进能否适用于新样例。

### 2.3 最终要回答什么？

> 在其他条件相同时，怎样的数据和训练方式，能让记忆更新更可靠，并让后续任务做得更好？

保留训练前后的结果、典型成功与失败样例，以及额外的调用、时间和输入长度。一次实验的收益需要由这些记录证明，不能预先假定训练一定有效。

## 3. 其他值得深入的模块

下面的方向可以在对应问题出现后逐个展开，无需同时研究全部模块。

| 模块 | 什么时候值得研究？ | 可能的优化方法 |
| --- | --- | --- |
| **分段摘要 Episode** | 原文有的信息，摘要遗漏了；条件、否定或时间被改写了 | 比较不同切分方式；规定必须保留的信息；调整压缩程度；用原文检查摘要 |
| **历史检索** | 信息明明保存了，当前问题却找不到 | 比较关键词与语义查找；调整两者组合；先找较多候选，再挑最相关内容；当前事实查询优先选择有效版本，历史查询保留对应旧版本 |
| **上下文组装 Context Builder** | 找到了正确材料，却没有放进模型输入；或者输入里重复信息太多 | 调整不同内容的长度配额；改变排列顺序；去除重复；根据任务选择材料 |
| **当前任务状态 CTS** | 把“准备做”当成“已经完成”；忘记阻塞项；下一步安排错误 | 明确任务状态；要求进展有证据；依据工具结果更新；针对任务状态单独设计训练样例 |
| **主题整理 TP** | 同一主题跨越很多段历史，普通检索不够方便 | 比较启用和关闭 TP 的效果；调整主题划分；合并重复条目；尝试自动发现主题 |
| **系统运行与长期保存** | 处理越来越慢；后台任务结果迟到；多会话间记忆归属混乱 | 后台处理、缓存、版本检查、失败恢复；明确哪些记忆属于用户、会话或任务 |

这些都是待验证的方法。是否采用，应根据它解决的问题、实际效果和新增成本决定。

## 4. 每次研究都采用同一个小流程

为了理解技术选择与取舍，每个模块都按下面四步推进：

1. **指出一个具体问题。** 例如：“摘要经常丢掉限制条件。”
2. **选择两三个解决方法。** 例如：“调整提示词”“降低压缩程度”“增加原文检查”。
3. **在相同条件下比较。** 看错误减少多少，同时增加了多少调用、时间或输入长度。
4. **记录采用或暂缓的理由。** 让最后留下的技术选择都有可以解释的依据，并保留仍未解决的问题。

每个模块形成一份简短实验记录即可，至少包含问题、候选方法、比较结果和选择理由。先完成当前实验，再根据结果决定下一步。
